## 状態(GameData)
企画書 3.3 の `GameState` を、次のように広げた。

| 項目 | 内容 |
|---|---|
| deckCount | デッキ数(1〜8) |
| shoe | 残りのカード(企画書の remainingCards)。末尾から引く |
| discard | 使用済みカード |
| seen | このシューで表向きになったカード(出た順) |
| runningCount | ランニングカウント |
| bankroll / bet / lastBet | 所持チップ / 配る前のベット / 前回のベット |
| dealer / holeRevealed | ディーラーのカード / ホールカードを開いたか |
| hands / active | プレイヤーのハンド(スプリットで最大4) / 操作中のハンド |
| phase | betting / insurance / playerTurn / dealerTurn / roundOver |
| insurance | インシュランスの額 |

トゥルーカウントは状態に持たず、表示のたびに計算する(RC と残り枚数から必ず決まるため、ずれを防ぐ)。

## ロジックの決まりごと
- **カウントの対象**:表向きになったカードだけ。ホールカードは開いた時点で数える
- **確率とTCの分母**:「見えていないカード」= シュー + 伏せたホールカード。ホールカードを分母から外すと、プレイヤーが知りえない情報が漏れるため
- **確率**:区分(2〜9、10、絵札、A)の残り枚数 ÷ 見えていない枚数 × 100
- **ディーラーのピーク**:アップカードが A または10点のとき、配札直後にBJを確認。BJなら即精算
- **スプリット**:同じ点数の2枚(10/J/Q/K は同じ扱い)。最大4ハンド。エースは1枚ずつで終了、再スプリット不可。スプリット後の 21 はBJ扱いにしない
- **ダブル**:最初の2枚のとき(スプリット後も可、スプリットしたエースは不可)
- **シャッフル**:ラウンド終了後に `配った枚数 ÷ 全枚数 ≥ 0.75` ならシャッフル。万一ラウンド中にシューが空になったら、使用済みカードをシャッフルして続ける(カウントは0から)
- **ディーラーの自動進行**:650ms ごとに1枚。リセットや新しいラウンドで番号(roundToken)が変わったら中断する
- **CPU の席**:人数の半分(端数は右)を右側=自分より先に行動、残りを左側=自分より後に行動にする。配札は 右CPU → 自分 → 左CPU → ディーラー の順で2周
- **CPU の戦略**(簡易ベーシックストラテジー):ソフト17以下はヒット。ハード11以下はヒット、12〜16はディーラーのアップカードが7以上ならヒット、17以上はスタンド。ダブル・スプリット・インシュランスはしない。ベットは見た目用(10〜100からランダム)で、所持チップは管理しない
- **ディーラーが引くか**:自分・CPU の全員がバーストかナチュラルBJなら、ホールカードを開くだけで引かない
- **チャンス**:`chanceLevel(TC)`。0 = 非表示(TC < 1)、1 = chance?(TC ≥ 1)、2 = chance!(TC ≥ 2)。ブラックジャックになる確率 = 2 × A の枚数 × 10点札の枚数 ÷ (n × (n−1)) × 100(n = 見えていない枚数)。ふだんの値はシャッフル直後の同じ式(1デッキで約4.83%、6デッキで約4.75%)
- **カード一覧(七並べ)**:`countBySuitRank(見えていないカード)` でマーク×数字ごとの残り枚数を数える(伏せたホールカードは「残り」に入れる)。並びは `SEVENS_ORDER`(A, 2〜10, J, Q, K)。色分けは `remainLevel(残り, デッキ数)`:0 = 残りなし(点線の空きマス)、6 = 全部残っている、1〜5 = 残りの割合 × 5 を切り上げ。6デッキなら ①〜⑥ がすべて別の色になる
- **チップと所持金**:所持チップはゲームのストアの `bankroll` が持つ(テーブルとの二重管理を避ける)。保存する値は `bankroll + 配札前のベット`。配札後の賭け金は含めないので、ラウンドの途中で再読み込みすると、その賭け金は失われる(再読み込みで負けを取り消せないようにするため)。所持金と最後にボーナスを受け取った日は `useWallet`。保存先は同じ `prob21-wallet`({chips, money, lastBonus})で、書くときは読み直して一部だけ上書きする
- **ログインボーナス**:端末の日付(YYYY-MM-DD)が `lastBonus` と違えば受け取れる。+20,000
- **交換**:1チップ = 所持金 20。整数枚だけ。足りなければ何もしない。チップ→所持金は、テーブルに賭けていないチップだけ
- **チップがなくなったとき**:betting / roundOver で `bankroll + bet < 1` なら、roundOver は 2.4秒、betting は 0.8秒 待ってチップを用意する画面へ移る
- **デッキ数のおすすめ**:ゲーム画面を開いたときに `deckCount ≥ 3` かつ `hideDeckTip` が false なら表示
- **開発用フック**:開発サーバーのときだけ `window.__store` にストアを置く(画面確認用。本番ビルドには含まれない)
- **解説用の記録(roundLog)**:カードが表になるたびに `{カード, 誰のカードか, 引く前のRC, 引く前の見えていないカードのランク別枚数, その合計}` を記録する。引いた後の値は、そこから1枚引いて計算する。配札のたびに空にする
- **設定の反映**:デッキ数・CPU 人数は、ラウンドの途中でも反映する。その場合は、テーブルのカードを片付け、賭けたチップ(インシュランスを含む)を返す
- **クイズの問題**:確率クイズは、のこり枚数を 10/20/25 にして、割り切れる%にする。トゥルーカウントは RC = TC × デッキ数 にして、割り切れる数にする。選択肢には、まちがえやすい答え(2倍、半分、1枚ずれ、RC をそのまま答える など)を入れる
- **効果音**:テーブルのカード枚数が増えたら配る音、ベットが増えたらチップの音、シャッフルしたらシャッフルの音、ラウンド終了時に自分の収支で勝ち/負け/引き分け(BJ があれば BJ の音)

## 結合テストの観点(06で使う)
- 配札後、seen が3枚で、RC がその3枚の合計になる
- スタンド → ディーラーが S17 まで引く → 精算、の流れで RC = seen の合計
- BJ の即精算、インシュランスの精算、ダブル、スプリットのチップの増減
- 75%超でシャッフルされ、RC と seen が0に戻る
- リセットで初期状態に戻る
